# EPC-005: Transaction engine

## Summary

T2 is the shared engine every unit goes through (ADR 0005 section 5).

## Outcome

After this merges, every unit change is previewed, backed up, applied under intent, verified, receipted and revertible, and the baseline is captured.

## Deliverables

- transaction layer: `internal/engine/`
- baseline unit: `internal/units/baseline/`
- fault-injection harness: `internal/engine/` (build tag `faultinject`)

## Acceptance Criteria

- AC-1 When a step is killed at any boundary, the next start shall restore and resume to a verified state; evidence: the fault-injection stress run
- AC-2 When `revert --to baseline` runs on a fixture, the match digest shall pass and every left-out difference shall be listed with its origin; evidence: fixture tests
- AC-3 When a unit is restored or reverted, its dependants shall be marked stale and re-verified before apply or resume; evidence: tests
- AC-4 Nothing that an advertised point references is pruned; evidence: tests
- AC-5 Logs pass through one redactor, and failure records are written by the engine; evidence: tests
- AC-6 For each unit this epic owns, standalone apply and revert tests pass, and an interrupted revert resumes to the previous receipt; evidence: unit tests and the stress-run log
- AC-7 `wskit unmanage UNIT` and `wskit adopt UNIT` move a unit out of and into the records without changing the machine; evidence: tests
- AC-8 Content outside the kit's marked blocks in shared files stays byte-identical across apply, revert and unmanage; evidence: tests
- AC-9 `unmanage` removes active membership only: history, point references and a recorded match exception stay, as a tombstone; `adopt` transfers ownership back; a revert to baseline after adopt or unmanage passes; evidence: tests
- AC-10 An interrupted revert resumes from its persisted direction, target point and completed undo steps; a failed apply, an explicit revert and `resume --restore-only` are distinct; evidence: fault-injection tests
- AC-11 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies

## Out of scope

- accounts, SSH and firewall reverts (enabled with their units in P2 B)
