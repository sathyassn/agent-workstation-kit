# EPC-002: Public-safety scan hardening

## Summary

The public-safety scan must stop personal and identifying details from reaching this public repository without keeping a list of the names to stop, and without printing what it finds (ADR 0005 section 12). Re-scoped by operator decision (2026-11-23): deterministic detectors and the contributor's own identity block; a person-name warning is local and optional; the keyed list becomes an optional layer for private repositories. CodeFlow will own the general mechanism, and the kit adopts it when it exists. This is a security change and gets a cross-lineage review.

## Outcome

After this merges, a contributor or agent who adds personal or identifying details that the detectors recognise, or their own machine's identity, is stopped before push and in CI; a local, warn-only check flags likely person names before push; and nothing the scan finds appears in its output.

## Deliverables

- the scanner, detectors, identity check and exemption records: `tests/check_public_release.py` or its Go successor
- scanner tests: `tests/`

## Acceptance Criteria

- AC-1 Deterministic detectors that need no list (emails, phone numbers, IP and MAC addresses, real home paths, private DNS names, cloud account and project IDs, chat and tracker user IDs, secrets) block in the pre-push check and in CI, need no secret, and finish well under one second on a typical change (TSK-007); evidence: tests and CI runs
- AC-2 When the scan finds a value, the output shall show only file, line and rule; evidence: a test that checks the output
- AC-3 When an obfuscated value appears (zero-padded octets, glued prefixes, partial private prefixes, encoded or look-alike characters), the scan shall flag it; evidence: tests per case
- AC-4 Every blocking layer fails closed: a failed or empty file listing, a detector that raises or is skipped, an identity source that errors or returns nothing, incomplete history in CI, or exceeded caps ends with a nonzero exit and no success report; in CI the base revision's scanner judges the head as data only (TSK-007, TSK-008); evidence: negative tests on both OSes and the workflow
- AC-5 The scan's own tests and its exemption records are scanned too, with only documented synthetic values allowed; every exemption is a tracked record (exact path, exact value, reason, approver, expiry date), read from the base revision only, invalid once expired, and listed on every run (TSK-007); evidence: tests
- AC-6 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
- AC-7 The contributor's own identity, read where the check runs and never stored, blocks on Linux and macOS; in CI the commits' git identities are checked (TSK-008); evidence: tests
- AC-8 The keyed digest list is an optional layer, off by default, for private repositories (TSK-008); evidence: tests with a synthetic key
- AC-9 A local person-name warning on changed prose is optional, warn-only and time-boxed, never blocks a push, and never runs in CI (TSK-050); evidence: tests

## Out of scope

- the keyed values of a private repository's optional list, which live only in its untracked file or CI secret
- the general mechanism across repositories, which CodeFlow will own
