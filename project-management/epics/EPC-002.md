# EPC-002: Public-safety scan hardening

## Summary

The public-safety scan must catch private names without containing or printing them (ADR 0005 section 12). This is a security change and gets a cross-lineage review.

## Outcome

After this merges, maintainers can rely on the public scan to catch personal and private network names without the rule file or CI logs revealing them.

## Deliverables

- keyed matching and fail-closed rules: `tests/check_public_release.py` or its Go successor
- scanner tests: `tests/`

## Acceptance Criteria

- AC-1 When the HMAC key is missing in CI, the scan shall fail closed; evidence: a test
- AC-2 When a private name is found, the output shall show only file, line and rule; evidence: a test that checks the output
- AC-3 When an obfuscated value appears (zero-padded octets, glued prefixes, partial private prefixes), the scan shall flag it; evidence: tests per case
- AC-4 When the file listing fails or is empty, the scan shall fail; evidence: a test
- AC-5 The rule file and the scanner's tests are scanned too, with only listed synthetic values allowed; evidence: a test
- AC-6 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies

## Out of scope

- the keyed values themselves, which live only in an untracked file and a CI secret

- Surfaces: The public-safety scan and CI.
