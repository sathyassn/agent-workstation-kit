# EPC-014: Identity and accounts units

## Summary

Machine identity, accounts and git identity (ADR 0005 sections 6, 7).

## Outcome

After this merges, hostnames, accounts, groups and git identity are set and revertible, with homes archived before removal.

## Deliverables

- units: `internal/units/machineidentity/`, `internal/units/accounts/`, `internal/units/gitidentity/`

## Acceptance Criteria

- AC-1 macOS accounts are created with a disabled password; evidence: tests
- AC-2 An account home is archived before revert removes the account; evidence: tests
- AC-3 Linux admin hand-overs use `su -P`; evidence: tests
- AC-4 For each unit this epic owns, standalone apply and revert tests pass, and an interrupted revert resumes to the previous receipt; evidence: unit tests and the stress-run log
- AC-5 Account removal is refused until the home archive exists, and the archive ships in this epic; evidence: tests
- AC-6 Both account topologies (a separate working account plus an admin, or a single account) are supported, and revert never removes the account the person signs in with; evidence: tests
- AC-7 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
- AC-8 When an admin sets a person's password, the accounts unit warns that the existing login keyring (Linux) or login keychain (macOS) keeps its old password, and says how to change it (learnings batch 4, 2026-11-23); evidence: tests of the warning text

## Out of scope

- none
