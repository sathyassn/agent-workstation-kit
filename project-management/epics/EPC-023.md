# EPC-023: Stages and gates

## Summary

T3: stages and gates compose the units (ADR 0005 sections 2 and 6). The dead-man timer ships earlier, with the SSH and firewall units (EPC-015).

## Outcome

After this merges, the full setup runs as stages composing units, with gates, hand-overs and stable points.

## Deliverables

- stages and gates: `internal/planner/`, `internal/conductor/`

## Acceptance Criteria

- AC-1 When a unit is skipped or deferred, it shall count as verified for the stable point; evidence: tests
- AC-2 When a root approval is refused, no mutation shall start and a blocked hand-over is recorded; evidence: tests
- AC-3 `plan` narrows G1, G2, S4 and S5 to the selected units; a dropped gate is `skipped` and counts; a default `developer`/`standard` run on a portable machine reaches S6; evidence: tests
- AC-4 A unit or component unsupported on the target is `skipped` with its reason, never refused or failed; evidence: tests
- AC-5 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
- AC-6 Generated hand-overs follow the pilot rules (learnings batch 3, 2026-11-23): a staged checksum manifest never lists itself; a redirection in a root hand-over runs inside the root shell (`sudo bash -c '... > FILE'`); and the result goes to a file the supervising agent can read; evidence: generator tests for each rule
- AC-7 Every manual step a unit cannot automate follows one standard: The docs and the setup hand-over give each manual step where it occurs, with numbered steps, the exact value, how to verify and how to undo, in both OS versions where they differ, with sanitised screenshots (TSK-049); screenshots are cropped to the panel, sanitised, named by step and OS, scanned by the public-safety scan and checked visually in review (TSK-049, learnings batch 4, 2026-11-23); evidence: the standard, the screenshot set and its review record
