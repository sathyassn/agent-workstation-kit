# EPC-010: Resources unit

## Summary

The machine-wide resource ceiling for agent work (ADR 0005 section 7a), moved early because a pilot host kept thrashing. It is the first unit right after T2, which provides the root baseline it needs. Pilot hosts are covered meanwhile by the frozen script fix.

## Outcome

After this merges, agent work runs under one ceiling with a reserve, early OOM handling and a `/tmp` policy, admitted by pressure.

## Deliverables

- unit: `internal/units/resourcelimits/`
- defaults: `registry/presets.toml` (the defaults table, principle 13)
- page: `docs/`

## Acceptance Criteria

- AC-1 An agent-work cgroup ceiling applies MemoryHigh and MemoryMax to the subtree where agent work runs, not the whole user slice, sized from a reserve: the reserve-based formula that TSK-034 implemented in the frozen script (the "Reserve-based sizing" table in `docs/07-security-and-resources.md`), ported unchanged; evidence: tests at 16, 60, 128 and 512 GiB
- AC-2 systemd-oomd, or a documented equivalent, is enabled with pressure settings for that subtree; on macOS, launchd and taskpolicy equivalents apply, with the memory-ceiling gap recorded; evidence: tests
- AC-3 Zram is sized as a share of RAM and agent-work swap (`MemorySwapMax`) follows the TSK-034 formula, an absolute value capped at 8 GiB; `/tmp` is kept disk-backed or caches are redirected off tmpfs, and disk free-space floors are checked with cache-cleanup guidance; evidence: tests
- AC-4 Each setting applies its best-practice default when unset, shows it in `plan` with its reason and source, and every opt-out works (principle 13); evidence: tests
- AC-5 Admission reads pressure data, not fixed numbers; PSI thresholds for `systemd-oomd` and admission stay percentages; evidence: tests
- AC-6 CPU follows the TSK-034 formula: a lower `CPUWeight` for agent work than for system and desktop, reserved cores, and an agent-slice `CPUQuota` for the rest; runner concurrency comes from free memory per measured job size and from cores; evidence: tests
- AC-7 `plan` shows each memory and CPU value with its derivation, and an explicit GB or core count overrides the formula and is labelled; evidence: tests
- AC-8 The doctor measures the non-agent baseline over time (the p95 of `system.slice`, the desktop session and the agent manager's own app); the measured fixed part of the reserve is that p95 times 1.5, replacing the role default. It reports when the reserve is below that need or far above it; evidence: tests
- AC-9 On macOS, the baseline comes from `footprint` in the root audit step, and from `ps` RSS for the user-level estimate, labelled approximate; evidence: tests with fake tools
- AC-10 On macOS, the default, utility and background QoS levels are measured on Apple silicon (build time, I/O throughput, desktop responsiveness); utility is the default unless the numbers say otherwise, and the measurements are recorded; evidence: the measurement record
- AC-11 A macOS agent-work wrapper starts agent terminals at the chosen QoS (a terminal shell) and agent services through launchd `ProcessType`; evidence: tests and a run on a macOS test host
- AC-12 For each unit this epic owns, standalone apply and revert tests pass, and an interrupted revert resumes to the previous receipt; evidence: unit tests and the stress-run log
- AC-13 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
