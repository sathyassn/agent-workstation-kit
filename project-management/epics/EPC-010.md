# EPC-010: Resources unit

## Summary

The machine-wide resource ceiling for agent work (ADR 0005 section 7a), moved early because a pilot host kept thrashing. It is the first unit right after T2, which provides the root baseline it needs. Pilot hosts are covered meanwhile by the frozen script fix.

## Outcome

After this merges, agent work runs under one ceiling with a reserve, early OOM handling and a `/tmp` policy, admitted by pressure.

## Deliverables

- unit: `internal/units/resourcelimits/`
- defaults: `registry/presets.toml` (the defaults table, principle 13)
- page: `docs/`

## Acceptance Criteria

- AC-1 An agent-work cgroup ceiling applies MemoryHigh and MemoryMax to the subtree where agent work runs, not the whole user slice, sized by the one reserve rule in ADR 0005 section 7a: reserve = fixed part + 2% of RAM, MemoryMax = RAM - reserve, MemoryHigh = MemoryMax - min(10% of MemoryMax, 8 GiB). This is the formula TSK-034 implemented in the frozen script (the "Reserve-based sizing" table in `docs/07-security-and-resources.md`), ported unchanged; evidence: tests at 16, 60, 128 and 512 GiB
- AC-2 systemd-oomd, or a documented equivalent, is enabled with pressure settings for that subtree; on macOS, launchd and taskpolicy equivalents apply, with the memory-ceiling gap recorded; evidence: tests
- AC-3 Agent-work swap (`MemorySwapMax`) is sized from the swap device, min(25% of the swap device, 8 GiB), never from RAM; zram sizing follows TSK-034 with its value shown in `plan`; `/tmp` is kept disk-backed or caches are redirected off tmpfs, and disk free-space floors are checked with cache-cleanup guidance; evidence: tests
- AC-4 Each setting applies its best-practice default when unset, shows it in `plan` with its reason and source, and every opt-out works (principle 13); evidence: tests
- AC-5 Admission reads pressure data, not fixed numbers; PSI thresholds for `systemd-oomd` and admission stay percentages; evidence: tests
- AC-6 CPU follows the TSK-034 formula: a lower `CPUWeight` for agent work than for system and desktop, reserved cores (lowered on a 1 or 2 core machine so agent work keeps at least one core, and `CPUQuota` never below 100%), and an agent-slice `CPUQuota` for the rest; runner concurrency comes from free memory per measured job size and from cores; evidence: tests
- AC-7 `plan` shows each memory and CPU value with its derivation, and an explicit GB or core count overrides the formula and is labelled; evidence: tests
- AC-8 The fixed part of the reserve starts at the role default (2 GiB headless, 8 GiB with a desktop). Until a real p95 baseline exists, measurement is informational, as TSK-034 ships it. Once the doctor has measured the non-agent p95 over time (`system.slice`, the desktop session and the agent manager's own app), the fixed part becomes that p95 x 1.5, and the doctor reports a mismatch when the reserve is below that need or far above it; evidence: tests for both states
- AC-9 On macOS, the baseline comes from `footprint` in the root audit step, and from `ps` RSS for the user-level estimate, labelled approximate; evidence: tests with fake tools
- AC-10 On macOS, the default, utility and background QoS levels are measured on Apple silicon (build time, I/O throughput, desktop responsiveness); utility is the default unless the numbers say otherwise, and the measurements are recorded; evidence: the measurement record
- AC-11 A macOS agent-work wrapper starts agent terminals at the chosen QoS (a terminal shell) and agent services through launchd `ProcessType`. The agent manager stores its terminal shell internally with no CLI, so setup prints a hand-over naming where to set it, the value (`agent-work-shell` on Linux, the wrapper on macOS) and how to verify it, and a request to the agent manager for a settings CLI is recorded; evidence: tests, the hand-over text and a run on a macOS test host
- AC-12 On macOS, the resources unit ships a small runner library and wrapper that read the memory-pressure level and apply the admission and stop policy; the agent tooling calls it and decides when. At warn the library stops admitting heavy jobs, and at critical it stops the newest heavy job; evidence: tests with a fake pressure source for each level
- AC-13 For each unit this epic owns, standalone apply and revert tests pass, and an interrupted revert resumes to the previous receipt; evidence: unit tests and the stress-run log
- AC-14 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
