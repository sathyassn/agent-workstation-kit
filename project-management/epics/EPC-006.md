# EPC-006: Browser tunnel unit

## Summary

The browser tunnel finishes remote sign-ins in the client's browser (ADR 0005 section 10a). It is the first unit, built on T1.

## Outcome

After this merges, a person can finish a remote CLI's localhost sign-in in their own browser over a loopback-only tunnel that closes itself.

## Deliverables

- unit: `internal/units/browsertunnel/`
- parity fixtures: `testdata/tunnel/`
- page: `docs/`

## Acceptance Criteria

- AC-1 When the redirect host is not localhost, 127.0.0.1 or ::1, no forward shall open; evidence: tests
- AC-2 When the workstation prints a fake readiness line, the browser shall not open; evidence: tests
- AC-3 When the time limit passes, the watchdog shall close the tunnel even if the client died; evidence: tests
- AC-4 When a port is in use, the tunnel shall be refused; evidence: tests
- AC-5 The hook never prints a URL; evidence: tests
- AC-6 Every behaviour in SPC-002's parity list passes as a Go test; evidence: the test list
- AC-7 For each unit this epic owns, standalone apply and revert tests pass, and an interrupted revert resumes to the previous receipt; evidence: unit tests and the stress-run log
- AC-8 Each tunnel's lifetime is owned by a supervisor job (systemd user unit or launchd agent job) that acknowledges the deadline before `ssh` starts; evidence: tests
- AC-9 Fixtures under `testdata/tunnel/` are written fresh and pass the public-safety scan; evidence: the scan
- AC-10 The tunnel works where one account owns both the hook store and the fetch (a single account, or a person who runs agents in their own account); for a separate agent account the unit is `skipped` with its reason and recorded as a capability gap; evidence: end-to-end tests of both cases
- AC-11 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies

## Out of scope

- macOS workstations (a recorded gap)
