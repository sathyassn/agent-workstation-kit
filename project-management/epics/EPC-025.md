# EPC-025: One config and the interview

## Summary

T5: one config and the interview (ADR 0005 sections 2b, 2e, 8).

## Outcome

After this merges, a person or agent can write a machine config through the interview, with layered values, `[tools]` and `[mcp]` choices and generated docs.

## Deliverables

- interview and schema 4: `internal/schema/`
- generated reference: `docs/reference/`

## Acceptance Criteria

- AC-1 `wskit config explain` shows each effective value and its layer; evidence: tests
- AC-2 The generated reference is current in CI; evidence: the staleness check
- AC-3 The interview asks purpose, then tier, then shows the plan, in quick or custom mode; evidence: teatest
- AC-4 The same answers through the interview or through `--set`, `--add`, `--remove` and `--config` give the same config and plan digest; evidence: tests
- AC-5 This epic owns the interview's questions, its flags, `interview --json`, `--answers` and the digest parity; TSK-017 provides only the rendering shell; evidence: the task records
- AC-6 Every input has a default or a derived default (machine name from a validated naming pattern, account names, mesh-VPN hostname, tags and auth method with interactive sign-in by default, exit-node and route acceptance off, remote-desktop choice, timezone and locale from the OS), shown with its why and risk; git identity is asked with no guessed value; secrets have no default and are never stored in config; evidence: tests
- AC-7 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
