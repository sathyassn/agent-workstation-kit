# EPC-001: Foundation for the Go kit

## Summary

The kit moves to one Go binary (ADR 0005 section 2b). Before any unit code, the repository needs the module, layout, CI, release build, code generation and the day-zero script.

## Outcome

After this merges, contributors can build, lint, test and release a signed `wskit` for Linux and macOS from this repository.

## Deliverables

- Go module, toolchain pin and tool pins: `go.mod`, `assets.go`
- CI for Go: `.github/workflows/`
- release build and checksums: `.github/workflows/`, `docs/maintenance/releasing.md`
- code generation from the schema: `internal/schema/`, `schema/`, `registry/units.toml`
- day-zero script: `scripts/bootstrap.sh`
- CodeFlow test config and stack standards: `.codeflow/test-config.json`, `AGENTS.md`

## Acceptance Criteria

- AC-1 When a PR changes Go code, CI shall run gofmt, goimports, go vet, golangci-lint with `.golangci.yml`, go test and govulncheck on Linux and macOS, and fail on any finding; evidence: a CI run with a planted lint error that fails
- AC-2 When a release is built, CI shall produce binaries for linux/amd64, linux/arm64 and darwin/arm64 with CGO_ENABLED=0 and a checksum file ready for the owner's signature; evidence: the release job's artifacts
- AC-3 When `schema/` or `registry/units.toml` changes without regenerated Go code, CI shall fail; evidence: a CI run on a stale change
- AC-4 When `bootstrap.sh` runs with a binary whose signature or checksum does not verify, it shall stop before running it; evidence: shell tests under a fake download
- AC-5 Every action in `.github/workflows/` is pinned by commit SHA, and every Go dependency and tool has an exact version and a registry entry; evidence: the repository check
- AC-6 Release tags follow `1.0.0-alpha.N`, `-beta.N`, `-rc.N`, then `1.0.0`; the frozen Python line keeps `0.2.0-rc.N`; evidence: the release workflow and `docs/maintenance/releasing.md`
- AC-7 Coverage floors on `internal/engine`, `internal/planner` and `internal/schema` are set and enforced in CI; evidence: CI
- AC-8 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
