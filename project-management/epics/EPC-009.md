# EPC-009: Agent settings unit

## Summary

Agent settings for every config home (ADR 0005 section 10, T7).

## Outcome

After this merges, every agent config home gets the declared settings and narrow sandbox exceptions.

## Deliverables

- unit: `internal/units/agentsettings/`

## Acceptance Criteria

- AC-1 When several agent-manager profiles exist, every config home shall get the declared settings; evidence: tests
- AC-2 Each sandbox exception is an exact command with a reason and undo; evidence: tests
- AC-3 Each agent CLI gets a no-prompts mode with a configurable default: Claude Code `bypassPermissions` with `skipDangerousModePermissionPrompt`; Codex `approval_policy = "never"` with `default_permissions = ":workspace"`; Grok `[ui] permission_mode = "auto"`, with Grok's always-approve mode offered only as an opt-in; agy `agentMode = "auto"` (agy validates the value; `--mode` sets it per run, with the values `accept-edits`, `auto` and `plan`); evidence: tests
- AC-4 The modes and settings apply to every config home, including each agent-manager profile's Claude Code home and each account's Codex home; the agent manager's own Codex runtime home is manager-owned, left unchanged and documented; evidence: tests
- AC-5 The kit never writes `defaultMode` at project scope; the doctor reports project-level settings in the configured code roots that override the user-level mode (CodeFlow v4 drops the project permission mode); evidence: tests
- AC-6 Codex folder trust for the user's repositories is synced into every Codex home from an owner allowlist, so third-party clones are excluded; the sync runs after a clone and when Codex asks, and the doctor reports untrusted repositories; evidence: tests
- AC-7 Upkeep runs at triggers, never on timers: kit setup and clone steps call the trust sync, the doctor reports untrusted repositories and sandbox placeholders, and the installed agent guidance names the triggers; evidence: tests and the guidance text
- AC-8 The Claude Code Linux sandbox leaves 0-byte read-only placeholders in `.claude` for protected paths. Only a 0-byte read-only file with one of these exact names is a candidate: `agents`, `commands`, `hooks`, `skills`, `workflows`, `routines`, `output-styles`, `launch.json`, `loop.md`, `scheduled_tasks.json`, `settings.local.json`. The doctor reports candidates. Removal runs only on demand, at a trigger the person starts (no automatic or scheduled cleanup, by user decision), by exact path, and only when no sandboxed process uses the folder; kit tools tolerate the placeholders; evidence: tests, including one that leaves unrelated empty files and non-empty files with those names untouched
- AC-9 agy gets one permission rule in `~/.gemini/antigravity-cli/settings.json` under `permissions.allow`, `command(regex:orca orchestration (worker-done|check|ask|reply|send)( .*)?)`, so workers report without a prompt and no other `orca` command is allowed; the worker brief names it and keeps "end with a report" as the fallback; evidence: tests and the brief
- AC-10 Verify checks agy's effective mode, not only the file: agy can rewrite `settings.json` and drop a saved `agentMode`, and with no saved mode it runs in Auto (seen on a macOS test host); evidence: tests
- AC-11 For each unit this epic owns, standalone apply and revert tests pass, and an interrupted revert resumes to the previous receipt; evidence: unit tests and the stress-run log
- AC-12 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
