# EPC-004: Terminal UI and plain output

## Summary

People get a guided terminal UI and agents get plain or JSON output, from one rendering layer over typed events (ADR 0005 section 2b, T1d).

## Outcome

After this merges, people get the guided terminal UI and agents get stable JSON and plain output from the same events.

## Deliverables

- rendering layer and front ends: `internal/ui/`

## Acceptance Criteria

- AC-1 When `--json` is set, standard output shall carry only versioned JSON and standard error only plain lines; evidence: snapshot tests
- AC-2 When standard output or standard error is not a terminal, or WSKIT_PLAIN=1, or TERM=dumb, no prompt, colour or animation shall appear; evidence: snapshot tests
- AC-3 When a cancel is requested from the UI, the UI shall send one cancel request to the engine and stay up; evidence: teatest
- AC-4 Plan, progress, hand-over card and final report views have golden-file tests; evidence: teatest
- AC-5 Secret inputs are masked, and NO_COLOR is respected; evidence: tests
- AC-6 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
