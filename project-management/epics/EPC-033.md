# EPC-033: macOS indexing unit

## Summary

A unit that keeps file indexing off development files, where heavy file churn makes indexers use CPU and memory for days. On macOS it turns off Spotlight indexing and the FSEvents on-disk log on a dedicated APFS development volume, and only there; without one it hands over the folder-level steps. On Linux it checks GNOME localsearch (tracker3) and ignores development roots that lack `.git` markers. A standalone script on a macOS test host is the reference implementation.

## Outcome

After this merges, a developer or agent host on macOS gets its dedicated development volume excluded from Spotlight and the FSEvents on-disk log by default, after the File Provider check passes, with a revert to the state before the first apply. Without a dedicated volume, the person gets a System Settings hand-over and no volume-level change. On Linux, the person sees GNOME localsearch reported and development roots without `.git` markers ignored.

## Deliverables

- unit: `internal/units/indexing/`
- detection of development volumes: `internal/platform/darwin/`
- GNOME localsearch check and ignore list: `internal/platform/linux/`
- page: `docs/`

## Acceptance Criteria

- AC-1 A dedicated APFS development volume in the same container (a separate volume under `/Volumes` holding repositories, worktrees or `node_modules`) is detected and confirmed in the interview to adopt, or created on approval; the system volume is never accepted; evidence: tests
- AC-2 Volume-level settings apply only on the dedicated development volume, and only after the AC-5 check passes: apply turns Spotlight indexing off, removes the index store, writes `.fseventsd/no_log`, adds a Time Machine exclusion when a destination exists, and restarts `fseventsd` once; a keep-Spotlight option turns off only the FSEvents log. No other volume gets a volume-level change; evidence: tests with fake tools, including a refused volume left unchanged
- AC-3 The state before the first apply is recorded and revert restores it exactly; the first receipt is kept and a re-apply never overwrites it; the deleted index store is in the cannot-undo list, because macOS rebuilds it; evidence: tests
- AC-4 The default is on for `developer` and `agent-host` at every tier (principle 13), shown in `plan` with its reason and source, and the opt-out works; evidence: tests
- AC-5 Volumes holding File Provider data (a `.CloudStorage` folder, or a File Provider domain registered through `fileproviderctl`) are refused for volume-level settings; the preview lists every cloud sync root found; evidence: tests with fake tools
- AC-6 The default target is a dedicated APFS development volume in the same container, created on approval or adopted, and the per-volume settings apply only there, after the AC-5 check passes. Without one, nothing changes at volume level: the unit hands over a System Settings step that lists the development folders for the Spotlight privacy list, and uses `.noindex` only for kit-owned caches and build output; evidence: tests and the hand-over text
- AC-7 On Linux, the unit checks GNOME localsearch (tracker3), reports whether it runs and what it indexes, and adds ignore-list entries for development roots that lack `.git` markers; revert removes only the entries it added; evidence: tests with fake tools
- AC-8 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies

## Out of scope

- folders on the system volume, which System Settings handles
- Linux indexing changes beyond the AC-7 check, report and ignore-list entries
