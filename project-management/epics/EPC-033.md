# EPC-033: macOS indexing unit

## Summary

A macOS unit that stops Spotlight indexing and the FSEvents on-disk log on development volumes, where heavy file churn makes `fseventsd` and Spotlight use CPU and memory for days. A standalone script on the pilot Mac is the reference implementation.

## Outcome

After this merges, a developer or agent host on macOS gets its development volumes excluded from Spotlight and the FSEvents on-disk log by default, with an exact revert.

## Deliverables

- unit: `internal/units/indexing/`
- detection of development volumes: `internal/platform/darwin/`
- page: `docs/`

## Acceptance Criteria

- AC-1 Development volumes (separate volumes under `/Volumes` holding repositories, worktrees or `node_modules`) are detected and confirmed in the interview; the system volume is never accepted; evidence: tests
- AC-2 Apply turns Spotlight indexing off, removes the index store, writes `.fseventsd/no_log`, adds a Time Machine exclusion when a destination exists, and restarts `fseventsd` once; a keep-Spotlight option turns off only the FSEvents log; evidence: tests with fake tools
- AC-3 The previous state is recorded and revert restores it exactly; the deleted index store is in the cannot-undo list, because macOS rebuilds it; evidence: tests
- AC-4 The default is on for `developer` and `agent-host` at every tier (principle 13), shown in `plan` with its reason and source, and the opt-out works; evidence: tests
- AC-5 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies

## Out of scope

- folders on the system volume, which System Settings handles
- Linux, where no equivalent is needed
