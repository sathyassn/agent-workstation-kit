# EPC-022: Doctor and audits

## Summary

One read-only check of every unit (ADR 0005 section 10, T8).

## Outcome

After this merges, a person or agent can run one read-only check of every unit, drift and end-of-support date.

## Deliverables

- unit: `internal/units/doctor/`

## Acceptance Criteria

- AC-1 When live state differs from the receipts, the doctor shall exit 6 and name each difference; evidence: tests
- AC-2 The doctor warns 90 days before an OS end-of-support date; evidence: tests
- AC-3 Drift is reported per unit with adopt, re-apply and ignore; `setup` never overwrites a manual change without a choice; evidence: tests
- AC-4 An `audit-agent` unit runs the agent-account checks in S8b; `stable` is tagged only after its receipt is in the public export; evidence: tests
- AC-5 The doctor reports, from the pilot learnings (2026-11-22 and 2026-11-23): project-level agent settings that override the user-level mode; repositories untrusted in a Codex home; Claude Code sandbox placeholders in `.claude`, at their exact names; agent CLI auth checked from the context the agents use; `secret-tool` on Linux; and a resource reserve below the measured need or far above it. The owning units define each check (EPC-009, EPC-010, EPC-011); evidence: tests
- AC-6 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
- AC-7 The doctor and every root-run audit write the full report to the root log folder (ADR 0005 section 11: `/var/log/agent-workstation-kit/<run-id>/` on Linux, `/Library/Logs/agent-workstation-kit/<run-id>/` on macOS, files 0600), and a redacted summary with a `--json` form to the public export with a `latest` pointer; the screen shows the summary, the failures and the log path; masking applies to every form; evidence: tests on both OSes
- AC-8 The host checks follow the declared configuration (learnings batch 3, 2026-11-23): SSH login checks follow the declared account topology (single or separate); the configured remote-desktop service (NoMachine on Linux; Screen Sharing or NoMachine on macOS) is recognised, not failed; processes outside the agent-work ceiling are counted per session or scope with a restart hint, never listed one line per process (on macOS, the QoS check replaces the count); grants and firewall choices declared in the fleet config (a VPN sudoers rule, an agent-runtime grant, the mDNS choice) are reported as approved; an undeclared one still fails; evidence: tests for each case on both OSes
- AC-9 The doctor checks that a new agent terminal lands in the agent-work ceiling (the cgroup on Linux, the QoS on macOS) and points to the agent-manager hand-over when it does not (EPC-010 AC-11); evidence: tests
- AC-10 The doctor reports long uptime together with large swapped-out desktop processes on Linux, with a reboot-window hint; cold swap without pressure is not an error; on macOS, where no per-process swap figure exists, it reports long uptime with the memory-pressure history; evidence: tests with fake process and pressure data
