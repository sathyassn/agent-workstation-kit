# EPC-017: Remote desktop unit

## Summary

Remote desktop released only behind the firewall (ADR 0005 section 3).

## Outcome

After this merges, remote desktop is installed masked and released only behind the firewall.

## Deliverables

- unit: `internal/units/remotedesktop/`

## Acceptance Criteria

- AC-1 For each unit this epic owns, standalone apply and revert tests pass, and an interrupted revert resumes to the previous receipt; evidence: unit tests and the stress-run log
- AC-2 Each PR in this epic carries tests, an adversarial review of code and docs, an interruption stress run, a docs-only walkthrough by a fresh agent and a changelog entry; evidence: the PR bodies
- AC-3 `remote_desktop.mode` is `physical` by default where a person logs in locally and `virtual` only for headless machines; `physical` shares the console session, so one account never has two desktops, duplicate audio stacks or a second keyring daemon; on macOS the physical session is always shared (TSK-048, learnings batch 4, 2026-11-23); evidence: tests per mode and OS
- AC-4 `remote_desktop.privacy`, on for work machines, blanks the physical screen while connected (no fade effect) and locks it on disconnect, with the Wayland input limit and the macOS curtain-mode gaps stated (TSK-048, learnings batch 4, 2026-11-23); evidence: tests and the plan text
- AC-5 The docs and the setup hand-over give each manual step where it occurs, with numbered steps, the exact value, how to verify and how to undo, in both OS versions where they differ, with sanitised screenshots (TSK-049): the NoMachine client options and macOS Screen Sharing Standard against High Performance mode (TSK-048); evidence: the docs diff
