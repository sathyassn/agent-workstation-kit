# TSK-034: Reserve-based sizing in the frozen resource script

## Description

Replace plain percentages in `scripts/apply-resource-policy-linux.sh` with reserve-based sizing: keep what the rest of the machine needs (a fixed reserve plus 2% of RAM), give agent work the remainder, with the existing flags and profile fields as labelled overrides. This is a fix to the frozen script so the pilot host gets sensible limits before the Go resources unit (EPC-010) replaces it.

## Outcome

After this merges, a person applying the resource policy on any Linux machine from 16 GiB to 512 GiB gets limits sized from what the rest of the machine needs, and sees how each value was derived.

## Deliverables

- reserve formula and preview: `scripts/apply-resource-policy-linux.sh`, `scripts/lib/common.sh`
- profile fields and flags: `scripts/fleetctl.py`, `scripts/check-profile-migration.py`
- checks: `scripts/lib/phase_verification.py`, `scripts/validate-host.sh`
- tests and docs: `tests/test_resource_policy.sh`, `tests/test_fleetctl.py`, `docs/07-security-and-resources.md`, `docs/01b-profile-field-reference.md`

## Acceptance Criteria

- AC-1 The memory reserve, MemoryMax, MemoryHigh, agent swap and CPU quota follow the formula at 16, 60, 128 and 512 GiB with a desktop and at 16 GiB headless; evidence: tests/test_resource_policy.sh
- AC-2 Explicit flags and profile fields override the formula and are labelled in the preview; evidence: tests
- AC-3 Apply then revert is byte-identical and a repeat apply changes nothing; evidence: tests/test_resource_policy.sh
- AC-4 A person previews the policy on a Linux host and sees each value with how it was derived before applying; evidence: the preview test output (journey)
