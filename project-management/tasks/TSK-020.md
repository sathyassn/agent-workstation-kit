# TSK-020: Revert to a point, retention and stale dependants

## Description

Add stable points, `restore-points`, `revert --to` in reverse stage and dependency order with the interrupted-revert state machine, retention that never prunes what a point references, kept `.deb` files for downgrades, the protected-access closure, and stale marking of the transitive closure (T2). `unmanage` and `adopt` are TSK-025.

## Outcome

After this merges, a person can return a machine to its baseline or any stable point, or walk away from a unit without changing it.

## Deliverables

- points and revert: `internal/engine/`, `internal/cli/`

## Acceptance Criteria

- AC-1 `revert --to baseline` on a fixture passes the match digest and keeps the protected-access closure; evidence: fixture tests
- AC-2 An interrupted revert resumes toward its target and never reapplies; evidence: fault-injection tests
- AC-3 Dependants of a reverted unit are marked stale and re-verified before apply; evidence: tests
