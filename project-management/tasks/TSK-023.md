# TSK-023: Contracts package, JSON schemas and fixtures

## Description

Publish SPC-001's contracts as a compilable Go package with no behaviour: the `Unit`, `Tx`, `DeclarativeTx` and `Sink` interfaces, the types `Description`, `Inputs`, `Plan`, `Receipt`, `Command` and `StateProvider`, the generated enums, the JSON schemas under `schema/json/` with golden fixtures, and the command matrix as a test table. Every later P1 task builds against it.

## Outcome

After this merges, every P1 builder works against one compiled set of contracts and fixtures.

## Deliverables

- interfaces and types: `internal/contract/` (SPC-001's package diagram puts every contract type there; `internal/engine/`, `internal/units/` and `internal/platform/` import it)
- schemas and fixtures: `schema/json/`, `testdata/json/`

## Acceptance Criteria

- AC-1 The package compiles and each interface has a fake that passes a contract test; evidence: `go test`
- AC-2 Each JSON schema validates its golden fixtures, and `next.outcome` allows only the listed values; evidence: tests
- AC-3 The command matrix is a test table that the CLI later runs against; evidence: the test file
- AC-4 A unit author builds a unit against `internal/contract`, runs it with the `contracttest` fakes and contract tests, and sees them pass, or fail naming the broken rule; evidence: internal/contract/contracttest tests (journey)
