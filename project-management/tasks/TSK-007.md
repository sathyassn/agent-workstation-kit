# TSK-007: Deterministic privacy scan that fails closed

## Description

Stop personal and identifying details from reaching this public repository without keeping a list of the names to stop (operator decisions, 2026-11-23). A hand-kept list of names does not scale and has to be kept secret itself. This task rebuilds the public-safety scan around detectors that need no list, keeps the hardened scanner core from PR #24 (decoding, normalisation, confusable characters, redacted output, the trusted base-branch workflow, size and count caps, and the fail-closed file listing), and replaces the free-form exceptions file with tracked exemption records. The scan blocks in the pre-push check and in CI and stays fast. It needs no secret, so fork and same-repository pull requests run the same checks. This is a security change and needs a cross-lineage review. Non-goal: the contributor's own identity and the optional layers (TSK-008, TSK-050); the general mechanism, which CodeFlow will own.

## Outcome

After this merges, a contributor or agent who adds an email address, phone number, private or public IP address, MAC address, real home path, private DNS name, cloud account ID or chat user ID to the repository is stopped before push and in CI, and sees only the file, line and rule.

## Deliverables

- scanner core and detectors: `tests/check_public_release.py`
- exemption records holding digests: `tests/public_scan_exemptions.json` (replaces `tests/public_scan_exceptions.json`), with the format documented in `docs/13-public-release-checklist.md`
- code-owner coverage of the scan's files: `.github/CODEOWNERS`
- CI wiring with no secret: `.github/workflows/public-scan.yml`, `.github/workflows/ci.yml`
- tests: `tests/test_public_release.py`, `tests/test_public_scan_hardening.py`
- removed from the blocking scan: the keyed rule file `tests/public_scan_rules.json` and the key steps in `docs/13-public-release-checklist.md`

## Acceptance Criteria

- AC-1 These detectors block with no list: email addresses; phone numbers; IPv4 and IPv6 addresses, private and public; MAC addresses; home-folder paths with a real-looking user name; tailnet and other private DNS names (`*.ts.net`, `*.internal`, `*.local`); cloud account and project IDs; chat and tracker user IDs; plus the existing secret scan. Only a documented allow list of exact values passes (for example the domains example.com, example.org and example.net, the documentation ranges 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24 and 2001:db8::/32, and the placeholder names in `AGENTS.md` such as `alice` and `host-a`), matched exactly after folding, never by substring; evidence: one test per detector with a hit, an allowed value and a near-miss of an allowed value
- AC-2 Before detection the scan decodes and folds every input: JSON and URL escapes, UTF-16 text, case, confusable look-alike characters, zero-padded octets, glued prefixes and partial private prefixes; a file containing NUL bytes is refused as binary unless a hash-bound binary exception names its exact content hash; evidence: one test per case
- AC-3 A finding prints only the file, line and rule, never the matched text; evidence: a test that checks the output
- AC-4 Every exemption is a tracked record with the exact path, the rule, a SHA-256 digest of the folded matched value (never the value itself), the reason, who approved it and an expiry date; exemptions for the optional keyed list use its keyed HMAC digest instead; a record that is past its expiry, has a missing or malformed date, or is incomplete fails the scan; exemptions are read from the base revision only, so an exemption added in the pull request under review does not apply to it; every configured exemption is listed in the output on every run, marked applied or unused, by path, rule and a short digest prefix, never the matched text; evidence: tests for a valid, an expired, an undated, a malformed and an incomplete record, an exemption added in the head revision, and the output
- AC-5 Every blocking path fails closed: a failed or empty file listing, a detector that raises or is skipped, a decode error, or a scan that exceeds its size or count caps ends with a nonzero exit and no success report; evidence: negative tests for each case on Linux and macOS
- AC-6 In CI the base revision supplies the scanner, its detectors, the mode configuration, the exemption records and the hash-bound binary exceptions, and the head revision is read as data only, so a pull request cannot change, disable or exempt its way past the checks that judge it; evidence: the workflow and test pull requests that each edit one of those files (delete a detector, set a mode to off, add an exemption, add a binary exception) and still fail
- AC-7 The scan runs in the pre-push check and in CI on Linux and macOS, needs no secret, and finishes well under one second on a typical change; evidence: CI runs on both OSes and a timing test on a typical diff
- AC-8 Each detector has the modes block, warn and off, block by default; every non-default mode is printed on every run, so a detector set to off can never make a silent clean result; evidence: tests of each mode and the output
- AC-9 The scan's own tests and its exemption records are scanned too, allowing only the documented synthetic values; because exemption records hold digests and never values, a real exemption never fails this self-scan; evidence: tests with a real exemption record
- AC-10 A contributor adds a line with a real-looking email address and a private IP address, and the push is refused with only the file, line and rule shown; after replacing them with documentation values it passes; evidence: the test transcript (journey)
- AC-11 Changes to the scanner, detector, mode configuration, exemption and binary-exception files, to the scan workflows (`.github/workflows/public-scan.yml` and `.github/workflows/ci.yml`) and to `.github/CODEOWNERS` itself go only through a reviewed pull request: `.github/CODEOWNERS` lists each of these paths, and the repository protection that TSK-040 sets up requires code-owner review for them; evidence: a repository check that every such path is covered by CODEOWNERS, the protection settings, and a test pull request that edits the workflows and CODEOWNERS and is held for code-owner review
