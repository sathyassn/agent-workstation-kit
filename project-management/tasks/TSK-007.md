# TSK-007: Deterministic privacy scan that fails closed

## Description

Stop personal and identifying details from reaching this public repository without keeping a list of the names to stop (operator decisions, 2026-11-23). A hand-kept list of names does not scale and has to be kept secret itself. This task rebuilds the public-safety scan around detectors that need no list, keeps the hardened scanner core from PR #24 (decoding, normalisation, confusable characters, redacted output, the trusted base-branch workflow, size and count caps, and the fail-closed file listing), and replaces the free-form exceptions file with tracked exemption records. The scan blocks in the pre-push check and in CI and stays fast. It needs no secret, so fork and same-repository pull requests run the same checks. This is a security change and needs a cross-lineage review. Non-goal: the contributor's own identity and the optional layers (TSK-008, TSK-050); the general mechanism, which CodeFlow will own.

## Outcome

After this merges, a contributor or agent who adds an email address, phone number, private or public IP address, MAC address, real home path, private DNS name, cloud account ID or chat user ID to the repository is stopped before push and in CI, and sees only the file, line and rule.

## Deliverables

- scanner core and detectors: `tests/check_public_release.py`
- exemption records: `tests/public_scan_exemptions.json` (replaces `tests/public_scan_exceptions.json`), with the format documented in `docs/13-public-release-checklist.md`
- CI wiring with no secret: `.github/workflows/public-scan.yml`, `.github/workflows/ci.yml`
- tests: `tests/test_public_release.py`, `tests/test_public_scan_hardening.py`
- removed from the blocking scan: the keyed rule file `tests/public_scan_rules.json` and the key steps in `docs/13-public-release-checklist.md`

## Acceptance Criteria

- AC-1 These detectors block with no list: email addresses (documentation domains such as example.com allowed); phone numbers; IPv4 and IPv6 addresses, private and public (documentation ranges such as 192.0.2.0/24 and 2001:db8::/32 allowed); MAC addresses; home-folder paths with a real-looking user name (placeholders such as `alice` allowed); tailnet and other private DNS names (`*.ts.net`, `*.internal`, `*.local`); cloud account and project IDs; chat and tracker user IDs; plus the existing secret scan; evidence: one test per detector with a hit and an allowed example
- AC-2 Decoding, normalisation and confusable-character folding run before detection, so an obfuscated value (zero-padded octets, glued prefixes, partial private prefixes, encoded or look-alike characters) is caught; evidence: one test per case
- AC-3 A finding prints only the file, line and rule, never the matched text; evidence: a test that checks the output
- AC-4 Every exemption is a tracked record with the exact path, the exact value or pattern, the reason, who approved it, and a review or expiry date; an expired or incomplete record fails the scan; exemptions change only through a reviewed PR; the scan output lists each exemption it applied as exempted, never silently; evidence: tests for a valid, an expired and an incomplete record, and the output
- AC-5 The scan fails closed when the file listing fails or is empty, and scans the exemption records and its own tests, allowing only documented synthetic values; evidence: tests
- AC-6 The scan runs in the pre-push check and in CI on Linux and macOS, needs no secret, and finishes well under one second on a typical change; evidence: CI runs on both OSes and a timing test on a typical diff
- AC-7 Each detector and the exemption policy are configurable, with every detector on and blocking by default; evidence: tests of the configuration
- AC-8 A contributor adds a line with a real-looking email address and a private IP address, and the push is refused with only the file, line and rule shown; after replacing them with documentation values it passes; evidence: the test transcript (journey)
