# TSK-032: macOS resource equivalents and defaults

## Description

Add the macOS equivalents (launchd limits and `taskpolicy` for agent work, with the memory-ceiling gap recorded in the capability matrix), the defaults table entries with their reasons and sources, and `wskit explain` output for each resource setting. It also owns the agent-manager terminal-shell hand-over on both OSes (EPC-010 AC-11): the agent manager stores its terminal shell internally with no settings CLI, so setup cannot script it.

## Outcome

After this merges, agent work on a Mac runs with the available limits, and every resource default explains itself.

## Deliverables

- unit: `internal/units/resourcelimits/`
- adapter: `internal/platform/darwin/`
- defaults: `registry/presets.toml`, `registry/sources.toml`
- agent-manager shell hand-over and its verify step: `internal/units/resourcelimits/` (both OSes)
- the recorded settings-CLI gap: `docs/11-primary-sources.md`

## Acceptance Criteria

- AC-1 On macOS, `plan` shows the applied limits and the recorded gap; evidence: tests with fake tools
- AC-2 `wskit explain` shows each resource default, its reason, its source and how to change it; evidence: golden tests
- AC-3 Setup prints a hand-over for the agent manager's terminal shell that names where the setting lives, the value (`agent-work-shell` on Linux, the agent-work wrapper on macOS) and the verify step, which checks that a new agent terminal runs inside the ceiling (its cgroup on Linux, its QoS on macOS); the hand-over's verify command passes on a correctly set terminal and fails on an unset one; evidence: golden hand-over text and tests with fake process data for both OSes (serves EPC-010 AC-11)
- AC-4 The agent manager's entry in `docs/11-primary-sources.md` records the missing settings CLI as a known gap, with a link to the request filed upstream and to the hand-over; evidence: the docs diff
