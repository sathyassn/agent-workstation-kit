# TSK-040: Two-step repository owner setup

## Description

Give the repository owner one command that sets up the repository's protection in two steps, so the setup that adds required checks never asks for a check that does not exist yet. The pilot work showed the order matters: keys, secrets, environments and pinned digests must exist before a workflow PR merges, and required checks and code-owner review can only be set once the workflows have run on the default branch. The repository owner runs the command; this task builds it. It previews by default, detects which checks exist, and is safe to rerun. It never stores or prints a secret value. Non-goal: organisation-level settings and private fleet repositories.

## Outcome

After this merges, the repository owner sets up a fresh copy of the repository by running the two steps in order, and a repeat run reports that nothing changes.

## Deliverables

- the command: `scripts/maintenance/owner-setup.sh` (provisional; the builder may make it a Go tool under `cmd/` instead, since new product code is Go), using only `gh` and `git`
- tests with a fake `gh`: `tests/test_owner_setup.sh` (provisional, follows the command's language)
- docs: `docs/13-public-release-checklist.md` (its repository-protection steps), `docs/maintenance/releasing.md`, `CHANGELOG.md`

## Acceptance Criteria

- AC-1 The `before-merge` step sets the keys, secrets, environments and pinned action digests that the incoming workflows name, reading those names from the workflow files; secret values come only from the owner at the `gh` prompt and are never printed, logged or stored; evidence: tests with a fake `gh` that record every call and check no secret value appears in output
- AC-2 The `after-workflows` step reads which check names exist on the default branch and sets required checks and code-owner review only for those; a check named by the policy that does not exist yet is reported, with the step to rerun later, and is not required; evidence: tests with present and missing checks
- AC-3 Both steps preview by default and change nothing without `--apply`; a repeat run with `--apply` on an already set-up repository makes no change and says so; evidence: tests for preview, first apply and repeat apply
- AC-4 The command runs on Linux and macOS with only `gh` and `git`, and refuses with a clear message when `gh` is not signed in as an owner of the repository; evidence: tests on both OSes in CI
- AC-5 The owner runs `before-merge`, merges a workflow PR, then runs `after-workflows`, and ends with every existing check required and a repeat run reporting no change; evidence: the test transcript against the fake `gh` (journey)
