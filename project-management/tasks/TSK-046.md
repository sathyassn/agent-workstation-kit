# TSK-046: Agent placement for every terminal and app

## Description

Put agent work inside the ceiling whatever starts it. Today the caps reach agents only because the agent manager's terminal-shell setting starts shells inside them; another terminal app, an SSH session or a GUI agent app escapes them. This task adds an `agent-placement` unit with layers: a guarded login-shell hook for the agent account, optional app launchers, the agent-manager setting documented as a guided step, and a verify that lists agent processes outside the cap and offers to move running ones. Each layer is a setting with a default shown in `plan`; revert removes the snippet, drop-ins and wrapper. Non-goal: the ceiling itself (TSK-030, TSK-032).

## Outcome

After this merges, an agent started from any terminal app, SSH or a configured GUI app runs inside the ceiling on Linux and at the agent QoS on macOS, and the person can see and move anything that still runs outside it.

## Deliverables

- the unit: `internal/units/agentplacement/` (new), registered in `registry/units.toml`
- platform pieces: `internal/platform/linux/` (scope move), `internal/platform/darwin/` (wrapper, LaunchAgent)
- docs and hand-overs: the unit's docs page, ADR 0005 sections 7a and 8a, `CHANGELOG.md`

## Acceptance Criteria

- AC-1 The shell hook, on by default for the agent account, is a guarded snippet in the zsh and bash login startup that re-execs an interactive shell into the cap once, with an environment guard against loops and a skip when already inside; Linux uses `systemd-run --user --scope --slice=agent-work.slice`, macOS uses `taskpolicy -c utility` plus `nice 5`; it works for every terminal app and SSH; evidence: tests for the loop guard, the skip, non-interactive shells and both OSes
- AC-2 Optional app launchers: on Linux, user-unit drop-ins and desktop-file overrides that start a chosen app in the agent slice; on macOS, a LaunchAgent or launcher wrapper for a chosen GUI agent app; evidence: tests of the generated files
- AC-3 Verify lists agent processes outside the cap (by cgroup path on Linux, by QoS and nice on macOS) and offers to move running ones, which runs only when the person chooses: on Linux `StartTransientUnit` with the PIDs of each agent terminal scope, stating that memory already charged stays with the old group until freed; on macOS `taskpolicy` and `renice` on the running PIDs; evidence: tests with fake systemd and process lists
- AC-4 Revert removes the snippet, the drop-ins, the overrides and the wrapper, and leaves the person's own shell startup lines untouched; evidence: tests
- AC-5 The agent-manager terminal-shell setting is a guided manual step in the docs and the setup hand-over: numbered steps, the exact value (the wrapper path), how to verify (a new terminal shows the agent-work cgroup on Linux, or utility QoS and nice 5 on macOS) and how to undo, for both OSes, pointing to its screenshots (TSK-049); evidence: the docs diff and the hand-over golden text
- AC-6 `plan` states the macOS gap: no group memory ceiling, QoS and nice only; evidence: the plan text
- AC-7 A person opens a terminal in a different terminal app and over SSH after apply, and both land inside the cap; evidence: the test transcript (journey)
