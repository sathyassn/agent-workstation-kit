# TSK-037: Logged, topology-aware host audit in the frozen scripts

## Description

Make the frozen host audit, `scripts/validate-host.sh`, usable on the pilot hosts before the Go doctor (EPC-022) replaces it. On a Linux pilot it printed about 1,200 lines to the terminal only, so neither the supervisor nor an agent could read the result. Most of those lines were false failures: checks that assume the separate-account topology on a single-account host, the remote-desktop service's own processes, one line per process outside the agent-work slice, and intended sudoers grants. This task writes the full report to the root log folder with a summary the supervising agent can read, and makes the checks follow what the fleet declares. It covers macOS and Linux. Non-goal: the mDNS firewall setting itself (TSK-038); this task only reports a declared mDNS choice as approved.

## Outcome

After this merges, a person runs the host audit on a Linux or macOS pilot host and sees a short summary with the real failures and the log path, and the supervising agent reads the same result from a file without asking the person to copy terminal output.

## Deliverables

- log, summary and declared-configuration checks: `scripts/validate-host.sh`, `scripts/lib/common.sh`
- the declared-configuration input (topology, remote-desktop service, approved grants and firewall choices) read from the machine profile through the exported plan or a flag: `scripts/fleetctl.py` (provisional; the builder picks the input path and records it in `AGENTS.md`)
- tests: `tests/test_validate_host.sh` (new) with fixture outputs for `sshd -T`, process lists, sudoers and systemd scopes
- docs: `AGENTS.md` sections 4 and 5, `docs/01b-profile-field-reference.md` for any new profile field, `CHANGELOG.md`

## Acceptance Criteria

- AC-1 When the audit runs as root, it writes the full report to `/var/log/agent-workstation-kit/<run-id>/` on Linux or `/Library/Logs/agent-workstation-kit/<run-id>/` on macOS (root 0700, files 0600, ADR 0005 section 11), and a redacted summary and a JSON summary to the public export (`/var/lib/agent-workstation-kit/public/` or `/Library/Application Support/agent-workstation-kit/public/`, files 0644) with a `latest` pointer; the screen shows only the counts, the failures and the log path; evidence: tests with a temporary root for both OS layouts (serves EPC-022 AC-7)
- AC-2 Masking applies to the log, the summary and the JSON: no secret, token or pairing link appears in any of them; evidence: a test that plants marker values and checks all three outputs (serves EPC-022 AC-7)
- AC-3 The SSH login checks follow the declared topology: with the separate topology, the agent account must be denied and left out of AllowUsers; with the single topology, where the person and the agent share one account and SSH to it over the mesh VPN is intended, those two checks are not run and the report says why; evidence: tests for both topologies (serves EPC-022 AC-8)
- AC-4 Processes of the declared remote-desktop service (NoMachine on Linux; Screen Sharing or NoMachine on macOS) are recognised and reported as the declared service, not as processes outside the agent account's slice; an undeclared service still fails; evidence: tests with fixture process lists (serves EPC-022 AC-8)
- AC-5 Processes outside the agent-work ceiling are reported as one line per session or scope with a count and the hint to restart those sessions, never one line per process; evidence: a test with a fixture of more than 1,000 processes that produces at most one line per scope (serves EPC-022 AC-8)
- AC-6 Sudoers grants and firewall choices declared in the fleet configuration (for example a VPN rule, an agent-runtime grant and the mDNS choice) are reported as approved, declared grants; any grant not declared still fails; evidence: tests with a declared and an undeclared grant (serves EPC-022 AC-8)
- AC-7 On macOS the audit writes the same log and summary and replaces the manual-evidence warning for remote desktop with the declared-service check; evidence: tests on the macOS branch with fixtures
- AC-8 A person runs the audit on a Linux host with the single topology and a declared remote-desktop service, gets a short summary with only real failures and the log path, and an agent reads the JSON summary from the public export; evidence: the test transcript (journey)
