# TSK-002: Go module, layout and pinned dependencies

## Description

Create the Go module at the repository's own path, the folder layout in docs/architecture.md, the root `assets.go` that embeds the data folders, and exact pins for every library and tool named in the P1 core spec, each with a registry entry and its review. No unit code.

## Outcome

After this merges, contributors can build an empty `wskit` and `agentctl` with every dependency pinned and recorded.

## Deliverables

- module and toolchain pin: `go.mod`, `go.sum`
- entry points: `cmd/wskit/main.go`, `cmd/agentctl/main.go`
- data embedding: `assets.go`
- dependency records: `registry/tools.toml`

## Acceptance Criteria

- AC-1 `go build ./...` succeeds on Linux and macOS with CGO_ENABLED=0; evidence: `make go-check` in this PR; the CI job lands in TSK-003
- AC-2 Every direct require and every `go tool` entry in `go.mod` has an exact version and a registry entry with its last review and its `go.sum` h1 sum, `go.mod` has no `replace` or `exclude`, and the indirect graph is held by `go.sum` integrity and govulncheck; evidence: `internal/registry` tests, including negative fixtures
- AC-3 `assets.go` embeds `schema/`, `registry/`, `dotfiles/` and `templates/`; evidence: a test that reads one file from each
- AC-4 A contributor clones the repository, runs `go build ./...`, and `go run ./cmd/wskit` and `go run ./cmd/agentctl` print their version; evidence: the commands in the PR (journey)
