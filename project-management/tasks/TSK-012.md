# TSK-012: Platforms, presets, planner and next

## Description

Detect the platform and admit only what `registry/platforms.toml` lists; resolve presets (purpose times tier) and form factor from `registry/presets.toml`; build the planner with per-OS dependency resolution, capability gaps and the plan digest; and serve `wskit next --json` and `wskit plan` (T1b).

## Outcome

After this merges, an agent can run `wskit plan` and `wskit next --json` on a supported machine and see exactly what would change.

## Deliverables

- platforms and presets: `registry/platforms.toml`, `registry/presets.toml`, `registry/capabilities.toml`
- planner: `internal/planner/`, `internal/platform/`
- conductor: `internal/conductor/`
- JSON schemas and fixtures: `schema/json/`

## Acceptance Criteria

- AC-1 Every purpose, tier, OS and form factor resolves with no unexpected failure; `full` equals the feasible units; skipped units carry reasons; evidence: tests
- AC-2 Form factor changes only the five listed defaults; evidence: a plan comparison test
- AC-3 `apply --platform` is refused; evidence: tests
- AC-5 `plan` narrows gates and stages to the selected units, a dropped gate is `skipped`, and a default `developer` run on a portable machine reaches S6; evidence: tests
- AC-6 Each account topology resolves its roles, conductor account, resource boundary and removable accounts as SPC-001's table states; evidence: tests
- AC-4 `next --json` matches its JSON schema and uses argument arrays; evidence: golden tests
