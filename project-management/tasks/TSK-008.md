# TSK-008: Contributor identity check and the optional keyed list

## Description

Stop a contributor or agent from committing their own machine's identity, read where the check runs and never stored, and keep the keyed digest list as an optional layer for private repositories (operator decisions, 2026-11-23). The deterministic detectors in TSK-007 cannot know a person's own name, account, host name or tailnet; the machine that runs the check does. The keyed HMAC list from PR #24 stays available, off by default, for organisation terms that no pattern can infer, such as customer names, in private repositories like the fleet. The earlier scope of this task (quiet output, obfuscation checks, self-scan) moved into TSK-007. Non-goal: the local person-name warning (TSK-050).

## Outcome

After this merges, a push that contains the pushing machine's own user name, full name, host name, computer names, git identity or tailnet names is refused on Linux and macOS, and a private repository can turn on a keyed list of its own terms.

## Deliverables

- identity collection and matching: `tests/check_public_release.py` (or a helper it calls), run by the pre-push check through `make ci-check`
- the optional keyed layer: the HMAC matching from PR #24, behind a setting that is off by default
- tests and docs: `tests/`, `docs/13-public-release-checklist.md`, `CHANGELOG.md`

## Acceptance Criteria

- AC-1 At check time the scan reads the local identity and never stores it: git `user.name` and `user.email`, the account name and full name, the host name, on macOS `scutil` ComputerName and LocalHostName, on Linux `hostnamectl`, and Tailscale node and tailnet names when Tailscale is installed; each value goes through the same decoding and folding as TSK-007 before matching, so a look-alike or padded form is caught; a match blocks the push and prints only the file, line and rule; evidence: tests with a fake identity on each OS, folded variants, and a test that no identity value is written to disk or output
- AC-2 The identity check fails closed: a source command that errors or times out, an empty or missing value from a required source (git identity, account, host name), or an error from an installed Tailscale ends with a nonzero exit and no success report; a Tailscale that is not installed is reported as absent; evidence: negative tests for each source on Linux and macOS
- AC-3 In CI, where the contributor's machine is not present, the check reads the git author and committer identities of every commit under review and fails closed when history is incomplete (a shallow clone without the base), when an identity is missing, or when the step itself does not run; the step is one of the required checks; its code comes from the base revision, as TSK-007 AC-6 does for the scanner, and its files are covered by `.github/CODEOWNERS` with code-owner review, as TSK-007 AC-11 does; evidence: tests, the workflow, the required-check list, a test pull request that weakens the identity check and still fails, and the repository check that CODEOWNERS covers its files
- AC-4 A CI run on a pull request whose commit author name appears in a changed file fails with only the file, line and rule; evidence: a CI run on a test pull request (journey)
- AC-5 The commit hooks are managed by CodeFlow, so the identity check runs at push time; the docs say so and name the CodeFlow mechanism that will add commit-time checks; evidence: the docs diff
- AC-6 The keyed digest list is a setting, off by default; its file holds only HMAC digests, and a plaintext or malformed entry fails the scan; when on, it matches by keyed HMAC with the key in an untracked file or a CI secret, fails closed when the key is missing, and never prints matched text; evidence: tests with a synthetic key and a plaintext entry
- AC-7 Both checks have the modes block, warn and off (identity block by default; keyed list off); every non-default mode is printed on every run; both use the tracked exemption records from TSK-007; evidence: tests
- AC-8 A contributor on macOS and on Linux adds their own host name to a doc, and the push is refused with only the file, line and rule; evidence: the test transcript (journey)
