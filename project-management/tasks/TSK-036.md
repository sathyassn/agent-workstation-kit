# TSK-036: Agent manual lessons and the plain-writing rule

## Description

Bring two sets of contributor guidance into the repository's own instructions. First, the operator's plain-writing rule from PR #3, rebased onto today's files: the agent manual, CONTRIBUTING, the pull-request template, the setup skill and the changelog. Second, the delivery lessons from the pilot work that a planning PR could not carry: renaming Orca worker branches before the first commit, each task PR carrying its own completion record with a matching Reviews row, bringing PRs current without force pushes, fast-forwarding the root checkout after merges, the first CodeFlow PR failing its gates by design, and the Go version line in `registry/tools.toml` as a security pin. From learnings batch 3 (2026-11-23): owner setup runs in two steps, before merge and after the workflows are on the default branch, through the command TSK-040 builds; a brief may name a fallback builder of another family when the coding agent is out of quota, recorded in the PR, with the cross-family reviewers unchanged, and drafts left by a stopped worker are untrusted and reviewed line by line; rerunning the full lint gate (with and without build tags) after every merge of `main`, because `main`'s linter configuration moves; that a branch name CodeFlow suggests can be refused by the kit's branch policy; the hand-over rules in section 6 (a redirection runs inside the root shell, results go to a file the supervising agent can read, a staged checksum manifest never lists itself); and a privacy lens on every review (operator decision, 2026-11-23): no personal names, emails, usernames, device or host names, home paths, private hostnames or addresses, tailnet names, account or tenant IDs or customer names, only placeholders such as example.com, alice, host-a and 192.0.2.x, with privacy findings reported like any other finding.

## Outcome

After this merges, an agent or contributor working in this repository finds the writing rule and the delivery lessons where they already look: `AGENTS.md`, CONTRIBUTING and the PR template.

## Deliverables

- `AGENTS.md` sections 6 and 7 and a writing rule
- `docs/13-public-release-checklist.md` (its repository-protection steps): a pointer to the TSK-040 command
- the review prompts in the PR template and `AGENTS.md` section 7: the privacy lens
- `CONTRIBUTING.md`, `.github/pull_request_template.md`, `skills/setup-agent-workstation/SKILL.md`
- `registry/tools.toml` header note on the Go version pin
- `CHANGELOG.md`
