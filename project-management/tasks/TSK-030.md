# TSK-030: Agent-work ceiling and early OOM

## Description

Build the `resource-limits` unit's Linux ceiling on T1's minimal engine: a dedicated agent-work slice with MemoryHigh and MemoryMax as shares of RAM (CPU as a share too), applied to the subtree where agent work runs, plus systemd-oomd with pressure settings or a documented fallback. The frozen script's fix in the pilot PR is the behaviour reference.

## Outcome

After this merges, agent work on a Linux machine runs under a memory and CPU ceiling with early OOM handling, applied and reverted by `wskit`.

## Deliverables

- unit: `internal/units/resourcelimits/`
- adapter: `internal/platform/linux/`

## Acceptance Criteria

- AC-1 The ceiling is computed from RAM at run time and never written as a fixed amount; evidence: tests
- AC-2 Apply then revert leaves the slice files and oomd settings byte-identical to before; evidence: tests in a test root
- AC-3 Work started outside the slice, and a user-level override that outranks it, are reported by `verify`; evidence: tests
