# TSK-035: StateProvider write in the contracts

## Description

Add a write method to `contract.StateProvider` so `Tx.SetState` can change non-file state: `Write(ctx, key StateKey, want State) error`. A follow-up of TSK-023, found while building TSK-013: the provider had Read, Snapshot and Restore only, and a Snapshot is opaque, so no real `SetState` could be built. The method follows the same rules as every mutating call: a key not declared in the unit's Description is refused, and the old state is snapshotted before the write.

## Outcome

After this merges, units and the engine can set and restore non-file state (hostname, firewall, sysctl and the other providers) through one contract that the fakes and contract tests enforce.

## Deliverables

- contract: `internal/contract/contract.go` (`StateProvider.Write`)
- fakes and contract tests: `internal/contract/contracttest/`
- engine use: `internal/engine/tx.go` `SetState` writes through the provider once the engine change is on main

## Acceptance Criteria

- AC-1 `StateProvider` has `Write(ctx, key, want)`; evidence: the package compiles and the fakes implement it
- AC-2 The contract test checks that an undeclared key is refused with `UndeclaredTargetError` and nothing changes, that Read after Write returns want, and that Restore of the snapshot taken before Write returns the old value; a broken fake fails each check; evidence: contracttest tests
- AC-3 A unit author calls `Tx.SetState` against the fakes and sees the state change and the change recorded for the receipt, or a refusal naming the undeclared key; evidence: contracttest tests (journey)
