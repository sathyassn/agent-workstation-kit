# TSK-044: Desktop-service ceilings and agent jobs in the ceiling

## Description

Keep everything agents start, and the desktop helpers that leak, under limits. On a Linux pilot two WirePlumber instances leaked about 4 GB each and used half a core each for days, found only by accident; and the capped job runner and rootless Docker started work in `app.slice`, outside the agent-work ceiling. This task adds per-service ceilings for known leak-prone desktop helpers, puts every agent-launched job and container runtime inside the agent-work ceiling, and adds a restart action for allowlisted services that a person triggers. Each is a setting with a default, shown in `plan` with its reason. Non-goal: the doctor's reports (TSK-047).

## Outcome

After this merges, a leaking desktop helper is capped and restarted by its service manager instead of filling memory for days, and no agent job or container escapes the agent-work ceiling on Linux; on macOS the equivalents are applied and the gaps are stated.

## Deliverables

- per-service ceilings, jobs and containers in the ceiling, the restart action: `internal/units/resourcelimits/`, `internal/platform/linux/`, `internal/platform/darwin/`
- the leak-prone service list and defaults: `registry/presets.toml`, `registry/sources.toml`
- docs and hand-overs: the resources unit's docs page, ADR 0005 section 8a rows, `CHANGELOG.md`

## Acceptance Criteria

- AC-1 `desktop_service_ceilings`, on by default, writes user-unit drop-ins for each service in the registry list (PipeWire, pipewire-pulse, WirePlumber, IBus and similar) with MemoryHigh, MemoryMax, CPUQuota and `Restart=on-failure`; the values are settings, `plan` shows measured normal use beside each ceiling, and revert removes only the drop-ins; on macOS `plan` states that launchd agents cannot be memory-capped; evidence: tests per service with fake systemd
- AC-2 `agent_jobs_in_ceiling`, on by default: the capped runner starts every job with `--slice=agent-work.slice` when the slice exists, and user drop-ins set `Slice=agent-work.slice` on rootless Docker (`docker.service`) and Podman services; on macOS the runner applies the agent QoS to its jobs, and the Docker Desktop and OrbStack VM memory settings are recorded as the cap through a guided manual step; evidence: tests of the runner arguments and the drop-ins, and the hand-over text
- AC-3 A restart action for allowlisted restart-safe services runs only when the person triggers it (`systemctl --user restart` on Linux, `launchctl kickstart -k` for allowlisted user agents on macOS) and never for system daemons or unlisted services; evidence: tests for allowlisted, unlisted and untriggered cases
- AC-4 Each manual step (the Docker Desktop and OrbStack memory settings) appears in the docs and in the setup hand-over where it occurs, with numbered steps, the exact value, how to verify and how to undo, for each OS where it differs, and points to its screenshots (TSK-049); evidence: the docs diff and the hand-over golden text
- AC-5 A person previews the resources unit on a Linux desktop with rootless Docker and sees each helper ceiling beside its normal use and Docker moved into the ceiling, applies it, and reverts it to the earlier state; evidence: the test transcript (journey)
