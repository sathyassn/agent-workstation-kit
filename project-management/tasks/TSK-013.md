# TSK-013: Minimal engine with durable intent and supervision

## Description

Build `engine.Tx` with file backups, atomic writes and receipts, the locks in their order, durable intent per operation, abandoned-run detection and the recovery claim, OS containment per apply with acknowledged identities, bounded shutdown, a minimal fault-injection harness (a `faultinject` build and a test root), and the `cmd/agentctl` skeleton (T1c). Root admission is TSK-024.

## Outcome

After this merges, a unit's file changes are backed up, receipted and recovered after any crash, and root runs only from the staged binary.

## Deliverables

- engine: `internal/engine/`
- containment adapters: `internal/platform/linux/`, `internal/platform/darwin/`
- sudo helper skeleton: `cmd/agentctl/`

## Acceptance Criteria

- AC-1 A kill at every boundary of an apply ends, after the next start, in a restored then reapplied state (apply intent only; revert recovery is TSK-020); evidence: the minimal fault-injection harness
- AC-2 A restart empties the containment within its bound or exits 4 without taking the lock; an active executor is told from an abandoned run by its identity; evidence: tests
- AC-3 A package-manager transaction is never killed by cancel or grace; evidence: tests
- AC-4 Concurrent apply and resume are serialized by the locks in their order; evidence: concurrency tests
- AC-5 A person whose apply was killed mid-run starts wskit again and finds the machine restored and the change reapplied, or is told with exit 4 that another run is still active; evidence: internal/engine kill and resume tests (journey)
