# TSK-047: Host health reports and the reboot plan

## Description

Add the host health reports the pilot hosts needed to the read-only doctor: runaway processes, more than one desktop, audio stack or keyring daemon per user, keyring health, slow DNS, and a plan for a coordinated reboot. Each was found by accident on a pilot: leaking desktop helpers for days, a remote-desktop session that started a second desktop, a locked login keyring that made agent CLIs hang, and Codex commands killed as "private address" because DNS lookups were slow under load. The doctor reports and points to the fix; it never restarts, unlocks or reboots anything. Non-goal: the fixes themselves (TSK-044, TSK-045, TSK-048).

## Outcome

After this merges, the doctor tells a person or agent, on Linux and macOS, about each of these conditions with its likely cause and fix, and gives a reboot plan that keeps every agent session resumable.

## Deliverables

- the checks: `internal/units/doctor/`, `internal/platform/linux/`, `internal/platform/darwin/`
- the reboot runbook: `docs/runbooks/coordinated-reboot.md` (new)
- docs: the doctor's docs page, ADR 0005 section 10, `CHANGELOG.md`

## Acceptance Criteria

- AC-1 The doctor reports a process above a CPU share for hours, or with steadily growing RSS or swap, with its unit and owner and the fix; for an allowlisted service it names the restart action (TSK-044) and never runs it; evidence: tests with fake samples over time on both OSes
- AC-2 The doctor reports more than one desktop session, audio stack or keyring daemon for one user, and names the remote-desktop mode as the likely cause; evidence: fixtures with two stacks
- AC-3 Keyring health: on Linux, one gnome-keyring-daemon per user and the login collection unlocked in an active desktop session, with a hint when the keyring password no longer matches after an admin set the login password and how to change it; on macOS, the login keychain unlocked and set as the default; evidence: tests with fake daemon lists and keyring states
- AC-4 DNS latency through the system resolver and each upstream is measured, flagged above about one second, and when a Codex log shows the private-address message the doctor reports "slow DNS (Codex #48766)" rather than a policy problem; evidence: tests with fake resolver latencies and a log fixture
- AC-5 `wskit doctor reboot-plan` (read-only) lists every agent terminal with its conversation ID and resume command (Claude from its session file, Codex from its open rollout file), the pause message and READY replies to collect, the reboot command that overrides desktop inhibitors only after the pause (`systemctl reboot --check-inhibitors=no` on Linux, `shutdown -r` on macOS), the checks after the reboot (keyring, ceiling, `/tmp`, swap, services), and the sessions to resume in their worktrees; evidence: tests with a fixture inventory
- AC-6 The runbook walks through the reboot plan on both OSes with numbered steps, verify and undo, and states that the agent manager restores many but not all sessions; evidence: the docs diff
- AC-7 A person runs the doctor on a Linux host with a second desktop session and a locked keyring, and sees both reported with the cause and the fix; evidence: the test transcript (journey)
