# TSK-004: Signed release build for every target

## Description

Build release binaries for linux/amd64, linux/arm64 and darwin/arm64 without cgo, publish a checksum file, and document how the owner signs it with the release key when publishing. The release workflow never holds the signing key.

## Outcome

After this merges, the owner can publish a release whose binaries and signed checksum file let anyone verify them with system tools.

## Deliverables

- workflow: `.github/workflows/release.yml`
- release steps: `docs/maintenance/releasing.md`

## Acceptance Criteria

- AC-1 A tag build produces the three binaries and a checksum file; evidence: the workflow run artefacts
- AC-2 The documented steps verify a binary with `ssh-keygen -Y verify` and the system checksum tool on Linux and macOS; evidence: a recorded run
- AC-3 No signing key or secret is used by the workflow; evidence: the workflow file
- AC-4 Tags follow `1.0.0-alpha.N`, `-beta.N`, `-rc.N` and `1.0.0`, and the changelog rules note catalog, registry and preset changes and one minor release of deprecation warning; evidence: the workflow and `docs/maintenance/releasing.md`
