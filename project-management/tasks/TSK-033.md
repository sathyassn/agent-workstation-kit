# TSK-033: Development volume detection and indexing apply

## Description

Build the macOS `indexing` unit: detect or create the dedicated APFS development volume and confirm it, refuse volumes holding File Provider data, turn off Spotlight indexing and the FSEvents on-disk log on that volume only (or only the log with keep-Spotlight), add a Time Machine exclusion when a destination exists, record the state before the first apply, and revert to it (EPC-033 AC-1 to AC-6). The standalone script on a macOS test host is the behaviour reference.

## Outcome

After this merges, a Mac's dedicated development volume stops costing CPU and memory to Spotlight and `fseventsd`, with a revert to the state before the first apply.

## Deliverables

- unit: `internal/units/indexing/`
- detection: `internal/platform/darwin/`

## Acceptance Criteria

- AC-1 The system volume is never accepted; evidence: tests
- AC-2 Apply then revert restores Spotlight and the FSEvents marker to the state before the first apply, and a re-apply never overwrites that first receipt; the removed index store is listed as cannot-undo; evidence: tests with fake tools
- AC-3 The default is on for developer and agent-host at every tier, and the opt-out works; evidence: tests
