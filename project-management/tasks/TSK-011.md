# TSK-011: Schema 3 parity, generated types and config layers

## Description

Declare today's schema 3 fields in `schema/`, generate Go types from them, implement layered config (kit, fleet, machine, user, environment, flags) with `wskit config get|set|explain|validate`, and prove parity with the Python validators (T1b).

## Outcome

After this merges, a person or agent can validate a profile with `wskit` and see each value's source layer.

## Deliverables

- schema: `schema/`
- validation and layers: `internal/schema/`
- parity fixtures: `testdata/profiles/`

## Acceptance Criteria

- AC-1 The Python and Go validators accept and reject the same fixtures; evidence: the parity test
- AC-2 `wskit config explain KEY` shows the effective value and its layer; evidence: tests
- AC-3 The safety floor cannot be set through any layer, and a refusal names the rule; evidence: tests
