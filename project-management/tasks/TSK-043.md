# TSK-043: macOS containment without a GUI session

## Description

Let the engine contain a command in the person's launchd user domain on macOS when no GUI session exists, for example during an SSH session. TSK-013 refuses user-scope containment unless the `gui/<uid>` domain exists, because launchd user agents are normally loaded there. This task finds the supported domain for a session without a GUI (`user/<uid>`), applies the same gate, identity, bootout and quiet-sample rules as the GUI domain, and keeps the refusal where neither domain is usable. The #33 security review recorded it as a follow-up. Non-goal: root (system-domain) containment, which TSK-013 covers.

## Outcome

After this merges, an agent working over SSH on a Mac with no one logged in to the desktop can run user-scope unit commands under containment, instead of being refused.

## Deliverables

- the user-domain path: `internal/platform/darwin/` (containment and inspector)
- tests with the real-shaped launchd fake, and docs: ADR 0005 section 8a (capability matrix row), `CHANGELOG.md`

## Acceptance Criteria

- AC-1 With no GUI session, user-scope containment uses the `user/<uid>` domain, with the same supervisor gate, recorded identity, acknowledged bootout and two consistent quiet samples as `gui/<uid>`; evidence: tests with the launchd fake for both domains
- AC-2 With neither domain usable, the engine refuses with a message that names the missing domain and the hand-over to fix it; evidence: tests
- AC-3 Recovery after a kill finds and empties a job in whichever domain it was started; evidence: kill-and-resume tests for both domains
- AC-4 The capability matrix records which domain each macOS session type uses; evidence: the docs diff
- AC-5 Over SSH on a Mac with no desktop login, an agent runs a user-scope unit command under containment and sees it emptied afterwards; evidence: a run on a macOS test host, recorded in the PR (journey)
