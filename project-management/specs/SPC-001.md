## Summary

The contracts that T1 (EPC-003 and EPC-004) and T2 (EPC-005) build
against. ADR 0005 (`docs/design/setup-architecture.md`) holds the decisions
and safety rules; this spec pins the interfaces, state machines, JSON shapes
and the tests that prove them. Each contract becomes a Go type, a JSON
schema under `schema/json/` or a fixture. TSK-023 publishes them as a
compilable package with fixtures before any other P1 code.

## Behavior

- **First install:** the mesh-VPN client is installed in S2 and enrolled at
  G1, before the `firewall` and `ssh` group, so the proof path exists. The
  group depends on `mesh-vpn` when remote access is selected; `mesh-vpn`
  never depends on the group's disarm. After the group, `next` returns
  `disarm` before any later root unit. A fresh first install is tested end
  to end.
- **S5 order:** `firewall` and `ssh` are ONE engine transaction under one
  dead-man arming: firewall rules, then the SSH change and the release of
  the SSH install guard, then the proof. Inside that transaction the steps
  do not block each other with exit 4. `vpn` and `remote-desktop` depend
  on the group's disarm. With remote access off, there is no timer and the
  proof is a console confirmation.
- **Proof by change kind:**
  - SSH or firewall changes need the mesh-VPN SSH proof when remote access
    is selected; otherwise a local console confirmation, with no timer;
  - VPN route changes are protected by the timer and verified by the route
    checks, a local confirmation, and the preserved mesh connectivity if
    present, never by an incoming-SSH proof.
  - Any other firewall-touching apply is refused while no proof is
    possible.
- **Order rules:** `setup --all` enforces stage order; `wskit UNIT` and
  `setup --unit` enforce only that unit's dependencies; a stale dependant
  waits until its dependencies verify.

### Presets, form factor, topology and platform

- **Presets** are purpose (`developer`, `agent-host`) times tier
  (`minimal`, `standard`, `full`), in `registry/presets.toml`. A machine's
  units are the preset plus the person's additions minus their removals.
  Units the preset leaves out, or that the capability matrix marks
  unsupported, are `skipped` with a reason, never refused or failed.
- **Presets narrow the gates.** `plan` keeps G1, G2, S4 and S5 only for the
  units selected; a dropped gate or stage is `skipped` and counts toward the
  stable point. A default `developer` and `standard` run on a portable
  machine reaches S6.
- **Which axis wins.** Purpose decides which units are selected. Form factor
  adjusts only the five listed defaults of selected units. An explicit
  setting overrides both. When an `agent-host` is portable, `plan` warns.
  Disk encryption on a portable machine is a safety requirement, not a
  default: it is a hand-over that refuses to continue until its probe
  passes.
- **Form factor** (`portable` or `fixed`) is detected (Linux chassis type;
  macOS model and battery) and can be overridden. It adjusts only: power and
  sleep behaviour, untrusted-network firewall defaults and roaming, incoming
  remote access (off by default when portable), the disk-encryption
  requirement, and sleep-aware backup timing. Each shows in `plan` with its
  reason.
- **Account topology,** asked in the interview after the tier, with the
  default from the purpose: `separate` for `agent-host`, `single` for
  `developer`. Roles are modelled separately from the number of accounts:

  | | Separate (default for agent-host) | Single (default for developer) |
  |---|---|---|
  | Accounts | admin, one per named person, agent | one account |
  | Roles held | admin: root steps; person: sign-ins, SSH; agent: agent work | all three |
  | Who may SSH | named people only; never the agent | the account, when SSH is selected |
  | Conductor runs | setup user until G2, then the agent account | that account throughout |
  | Revert may remove | accounts the kit created, never the one the person signs in with | none |
  | Resource boundary | the agent account's user slice | a separate agent-work slice for processes the agent manager starts, or an opt-in with the limit stated in `plan` |
  | Browser tunnel | `skipped` with its reason, recorded as a capability gap: the hook store is private to the agent account but the fetch runs as the person; a forced-command design is planned after 1.0 | supported: one account owns the hook store and the fetch, over SSH as that account |

- **Audits.** `doctor` runs the root checks in S8a, and `audit-agent` runs
  the agent-account checks in S8b. `stable` is tagged only after the
  `audit-agent` receipt is in the public export.
- **Baselines.** The root baseline is required before any machine change
  (root scopes, and macOS `packages-user`, whose two S2 scopes are refused
  until the root baseline receipt is exported). A user-scope unit run on its
  own needs only an account-local baseline, kept in the account state.
- **Platform detection** admits only what `registry/platforms.toml` lists.
  `--platform OS-VERSION` and `--form-factor` are preview selectors for
  `plan`; `apply` refuses them. `--set`, `--add`, `--remove` and `--config`
  are persistent overrides written to the config. Windows is out of scope.

### Inputs and defaults

Every input has a default or a derived default, settable in the config and
shown and editable in the interview, with its why and risk:

- the machine name, from a validated naming pattern (purpose and form
  factor, or the fleet's pattern);
- account names;
- mesh-VPN hostname, tags and auth method (interactive sign-in by default;
  an auth key only as a secret hand-over), with exit-node and route
  acceptance off by default;
- the remote-desktop choice;
- timezone and locale, from the OS;
- git identity, which is asked with no guessed value.

Secrets have no default and are never stored in config; they are entered
at hand-overs. The interview's questions, flags, `interview --json`,
`--answers` and the digest parity belong to EPC-025; EPC-004 provides only
the rendering.

### Intent, recovery and revert

Each operation has its own record in its journal and its own recovery
path. The record names the operation: `apply`, `revert` or `restore-only`.

**apply**

```text
idle --write intent(apply, containment name)--> applying
applying --apply ok, verify ok, write receipt--> idle
applying --failure--> restoring --> restored --> idle (failure record)
start, record=apply/applying   --> stop executor if alive --> empty containment --> restoring --> reapply
start, record=apply/restoring  --> finish restore --> reapply
```

**revert --to POINT**

```text
idle --write record(revert, target, steps=[])--> reverting
reverting --undo step k ok, append k to completed steps--> reverting
reverting --all steps done, write receipt--> idle
start, record=revert/reverting --> resume at the first step not in completed steps (never reapplies)
```

**restore-only** (`resume --restore-only`)

```text
start, record=apply/applying|restoring --> restoring --> restored --> idle (stops; no reapply)
```

- Every record is written to a temporary file in the same folder, fsynced,
  renamed, and the folder fsynced. Order: the record before any change, the
  receipt after verify, the export after the receipt. At start, receipts
  are the authority for what is done.
- **An abandoned run is told from an active one by identity:** the record
  holds the executor's boot ID, process ID and start time. If a process with
  all three is alive, the run is active and a second executor exits 4;
  otherwise recovery starts.
- While a step's dead-man timer is armed, the dead-man machine below decides:
  only `disarm` or the timer may change the step.

### Locks

- The executor takes the host lock, then the journal lock, and never the
  dead-man lock.
- Arm, re-arm and disarm take only the dead-man lock: never the host or
  journal lock. An executor that holds the host lock can therefore wait for
  an arm acknowledgement without deadlock.
- A restore takes the dead-man lock, writes its claim, stops the executor,
  RELEASES the dead-man lock, then takes the host lock, then the journal
  lock.
- An account scope takes the account lock, then the account journal lock,
  and never a root lock.
- Race tests cover arm and re-arm crashes, competing restores, and the timer
  against disarm, apply and resume.

### Process supervision

1. Write the containment name (Linux transient scope, or macOS launchd job
   label) into the intent and fsync.
2. Start the containment and the tool inside it.
3. Wait for the launch acknowledgement, then record identities (boot ID,
   process ID, start time).
4. On restart: empty the containment within a bound (wait for the grace
   period, terminate, kill). A package-manager transaction is waited for,
   never killed. If it cannot be emptied, exit 4 without taking the lock.

### Cancellation

SIGINT, SIGTERM and a UI cancel become one cancel request to the engine.
The engine lets the step finish; at the end of the grace period it cancels
the step's context and empties its containment, except a package-manager
transaction. Exit 130. Bubble Tea runs with its signal handler off.

### Dead-man timer

The dead-man state lives in its own file, `deadman.json` in the root state
folder, separate from the journal, guarded by the dead-man lock.

```text
none --arm request--> arming --scheduler ack--> armed(deadline=now+30m, boot_id)
armed --apply done, re-arm request--> rearming --scheduler ack--> armed(deadline=now+10m)
armed --proof recorded--> proven
proven --disarm (other login session)--> disarming --units removed--> none
armed|proven --deadline passed--> claimed --executor stopped--> restoring --> restored-by-timer --> none
armed|proven at boot with a new boot_id --> claimed --> restoring (boot recovery, both OSes)
```

- Every transition writes its pending state (`arming`, `rearming`,
  `disarming`) and fsyncs before it touches the scheduler, and records the
  scheduler's acknowledgement after. At start, a pending state is
  reconciled against the scheduler: an unacknowledged arm is cancelled and
  its units removed; an unacknowledged re-arm keeps the earlier deadline;
  an unfinished disarm is finished.
- **No protected mutation starts before the arm is acknowledged.**
- **The claim.** A restore writes a claim (run ID, claimant boot ID, process
  ID and start time, and an expiry 5 minutes ahead) into the dead-man file
  before it acts. A claim is live while its claimant is alive and the
  expiry has not passed; a claimant renews it each minute. A dead or expired
  claim is taken over atomically by rewriting the file under the dead-man
  lock. A starting executor that finds a live claim exits 4.
- The restore re-reads the state immediately before changing anything,
  exits if the state is `disarmed`, and runs from the armed copy only after
  the system checksum tool verifies it.
- On macOS, the check job restores at once when the armed step's boot ID
  differs from the current boot.
- A revert keeps the proven mesh-VPN SSH path and its dependency closure
  (packages, account, keys, firewall rule). The match digest exempts exactly
  that closure, and the revert report prints it.
- Crash tests cover a kill inside every transition above.

### Torn states

| Operation | Interrupted at | What the next start finds | What it does |
|---|---|---|---|
| apply | writing the record | a temporary file, no record | removes it; nothing was applied |
| apply | during apply | `apply/applying` | stops the executor if alive, empties the containment, restores, reapplies |
| apply | after verify, before the receipt | `apply/applying` | restores, reapplies |
| apply | during restore | `apply/restoring` | finishes the restore, reapplies |
| revert | during an undo step | `revert/reverting` with completed steps | resumes at the first step not completed; never reapplies |
| revert | after the last step, before the receipt | `revert/reverting`, all steps completed | writes the receipt |
| restore-only | during restore | `apply/restoring`, marked restore-only | finishes the restore and stops |
| dead-man | during arm or re-arm | `arming` or `rearming` | reconciles with the scheduler |
| dead-man | during a restore | a claim | takes over the claim if its claimant is dead, then restores |
| dead-man | during disarm | `disarming`, or `disarmed` with units present | removes the units |
| any | writing the export | an old export | regenerates it from the receipts |

Tests interrupt each undo step of a revert and each restore step.

### Plans and approvals

- Plan digest: SHA-256 over the plan in canonical JSON (RFC 8785, one
  pinned library), without the digest field.
- **Approval binds every input.** Every file the plan read (profile, fleet
  files, templates, registry entries) is staged with the plan, and its hash
  is part of the digest. Approval records hold the plan digest, the fleet
  commit when there is one, the approving account and the time: root
  approvals in the root journal, user approvals in the account state.
- A root step checks the approval phrase and the digest once, before it
  takes any lock. After taking the locks, it re-checks the staged inputs'
  hashes and each step's preconditions before any mutation.
- **A refused root approval** (declined phrase, failed `sudo`) starts no
  mutation, records a `blocked` hand-over, keeps every earlier receipt and
  exits 3. The conductor reports it and does not retry until the person
  says so.

### Output

1. `--json`: the result as versioned JSON on standard output; events as
   JSON lines on standard error; tool output only in the log. `--json` wins
   over `WSKIT_PLAIN`.
2. `--plain` or `WSKIT_PLAIN=1`: plain lines, no prompts.
3. The terminal UI only when standard output and standard error are both
   terminals, `TERM` is not `dumb`, and neither of the above is set.
4. Otherwise plain.

Tool output never reaches the terminal in JSON or plain mode; the browser
hook's two non-secret lines are the one exception, and only when the hook
runs as the `BROWSER` program. Fang and other styling are off in JSON and
plain mode. One stage selector, `--stage`, takes the scope ID; there is no
`--scope`.

### Events

- Events carry a sequence number and are written to the run log in order;
  the run log is the record, and the UI is a view of it.
- The UI queue is bounded and never blocks a unit: when it is full,
  `Progress` events are coalesced with a count, and other events are
  delivered to the UI later by replaying the run log from the last sequence
  number the UI saw.
- `Tx.Emit` may block only while it writes a non-progress event to the run
  log. If the log cannot be written (disk full), the step fails closed: the
  engine records the failure in the journal and restores.
- Tests cover ordering, coalescing, replay after a stalled UI, a full disk,
  and bounded memory.

### No lock-in

- Drift is reported per unit; the person chooses adopt, re-apply or
  ignore. This is separate from in-flight recovery, which follows the
  intent machine above.
- `wskit adopt UNIT` writes the current state into the config; for a root
  unit or a fleet config it uses the draft-and-stop path (ADR 0005 section
  2e).
- `wskit unmanage UNIT` removes active membership only: history and point
  references stay as a tombstone, and an accepted match exception is
  recorded, so a later revert to baseline still passes. `adopt` transfers
  ownership back.
- Shared files are changed only inside the kit's marked blocks or its own
  drop-in files.

### Best-practice defaults (principle 13)

Every setting applies its best-practice default when unset, shows it in
`plan` with its reason, and is configurable or can be opted out. Defaults
come from one table, `registry/presets.toml`, and may differ by purpose,
tier and form factor. Each has a reason and a source in
`registry/sources.toml`, and `wskit explain SETTING` shows it.

| Setting | Default | Varies by |
|---|---|---|
| Agent-work memory and CPU ceiling | on, as shares of RAM and CPU | purpose (enforced on agent-host), form factor (battery-aware) |
| Early OOM handling | on: systemd-oomd, or launchd and taskpolicy on macOS | none |
| Swap and zram | sized as shares of RAM | form factor |
| `/tmp` | disk-backed, or caches redirected off tmpfs | none |
| Free-space floors | warn below a share of the disk, with cleanup guidance | none |
| Resource runner and sweep | wired into the agent settings bundle | tier (standard and full) |
| macOS development volumes | detected and confirmed; Spotlight and the FSEvents on-disk log off; Time Machine excluded when a destination exists | macOS only |
| Security hardening, pinned versions, update policy, log rotation | the kit's documented baseline | purpose |

Tests show each default is applied when the setting is unset, and that
every opt-out works.

### References

`wskit explain UNIT --sources` lists the unit's entries from
`registry/sources.toml` (link, purpose, last verified).

## Interfaces and formats

Package ownership: `internal/engine` owns `Tx`, `DeclarativeTx`, `Receipt`
and the event sink; `internal/units` owns `Unit`, `Description`, `Inputs`,
`Plan` and `Result`; `internal/platform` owns `StateProvider` and
`Command`. Enums (`UnitID`, `Stage`, `Scope`, `Verb`, `Outcome`,
`EventKind`, `StepID`, `DataKey`, `ExitCode`) are generated with `String()`
and validation.

```go
type Unit interface {
    ID() UnitID
    Describe(ctx context.Context) (Description, error)
    Plan(ctx context.Context, in Inputs) (Plan, error)
    Apply(ctx context.Context, tx Tx, p Plan) error
    Verify(ctx context.Context, p Plan) (Result, error)
    Revert(ctx context.Context, tx Tx, r Receipt) error
    Status(ctx context.Context) (Status, error)
}

// DeclarativeTx is what declarative units get: typed operations only, no Run.
type DeclarativeTx interface {
    WriteFile(ctx context.Context, path string, data []byte, perm fs.FileMode, owner Owner) error
    RenderTemplate(ctx context.Context, path string, tpl TemplateID, vars TemplateVars, perm fs.FileMode, owner Owner) error
    EnsureBlock(ctx context.Context, path string, b ManagedBlock) error
    RemoveBlock(ctx context.Context, path string, id BlockID) error
    Remove(ctx context.Context, path string) error
    Package(ctx context.Context, want PackageState) error
    Service(ctx context.Context, want ServiceState) error
    UserGroup(ctx context.Context, want UserGroupState) error
    Check(ctx context.Context, c CheckSpec) (CheckResult, error)
    Emit(e Event)
}

// Tx is what kit units get: the typed operations plus SetState and Run.
type Tx interface {
    DeclarativeTx
    SetState(ctx context.Context, p StateProvider, key StateKey, want State) error
    Run(ctx context.Context, c Command) (CommandResult, error) // argv, declared env, timeout, inside the containment
}

type Event struct {
    Seq   uint64
    Time  time.Time
    RunID RunID
    Unit  UnitID
    Step  StepID
    Kind  EventKind
    Text  string             // redacted, one line
    Data  map[DataKey]string // keys are generated constants
}

type Sink interface{ Deliver(Event) } // never blocks; see Events above
```

Every mutating call refuses a path or state not declared in `Describe`,
backs it up first, and records it for the receipt.

| Type | Holds |
|---|---|
| `Description` | unit, scope, depends_on, capabilities, owned paths, owned state keys, irreversible items, declared env |
| `Inputs` | the resolved config values for the unit, the platform facts, the form factor, the topology |
| `Plan` | plan ID, digest, changes (target, action, before and after digests, risk), non-defaults, blocked_by, cannot_undo, outcome |
| `Receipt` | run ID, unit, plan digest, changes made with backup references, time, outcome |
| `Command` | argv, declared env keys, working folder, timeout, whether it is a package-manager transaction |
| `StateProvider` | a named source of state (`hostname`, `ufw`, `unit-masks`, `sysctl`, `packages`, `accounts`, `launchd`, `app-firewall`) with Read, Snapshot and Restore |

JSON schemas in `schema/json/`, each with `schema_version`, golden fixtures
and a docs example: `describe`, `plan`, `next`, `status`, `explain`,
`handover`, `failure`, `event` and `error`. `next.outcome` is one of
`verified`, `skipped`, `deferred`, `failed`, `stale` or null.

| Schema | Fields |
|---|---|
| `next` | `run_id`, `stage`, `unit`, `owner`, `root`, `gate`, `preview_argv[]`, `apply_argv[]`, `handover`, `probe`, `log_path`, `blocked_by[]`, `outcome` |
| `handover` | `machine`, `account`, `step`, `command{argv[], display}`, `why`, `verify{argv[]}`, `undo`, `probe`, `status` (`open`, `blocked`, `done`) |
| `failure` | `unit`, `step`, `error_class`, `message`, `suggested`, `log`, `backup` |
| `explain` | `subject` (unit or field), `what`, `why`, `options`, `default`, `risk`, `undo`, `manual_equivalent`, `sources[]` |
| `event` | the `Event` fields above |
| `error` | `code`, `class`, `message`, `rule` (for refusals) |

**Command matrix** (who may run what):

| Command | Scope | Runs as | Modes |
|---|---|---|---|
| `plan`, `explain`, `status`, `next`, `doctor` | any | any account | read only |
| `setup --stage S`, `UNIT apply|revert` (user units) | user | that account | preview; `--apply` |
| `setup --stage S`, `UNIT apply|revert` (root units) | root | `sudo` staged binary | preview; `--apply` with the approval phrase |
| `resume`, `revert --to` | per journal | that journal's account | preview; `--apply` |
| `disarm` | root | `sudo`, another login session | `--apply` |
| `adopt`, `unmanage` | per unit | the unit's account; root and fleet configs draft and stop | preview; `--apply` |
| `config get|set|explain|validate`, `interview`, `migrate` | user | any account | preview for writes |

Tool environment allowlist: `PATH` (system default; Homebrew prefix first
for the macOS package owner), `HOME`, `USER`, `LOGNAME`, `LANG`, `LC_ALL`,
`TERM`, `TMPDIR`, `DEBIAN_FRONTEND=noninteractive` on Linux, plus variables
a unit declares.

Exit codes: 0 done; 1 failed; 2 refused or usage; 3 a person must act; 4
blocked by recovery (this journal's interrupted step, an active executor, or
an armed timer, with a pointer to `disarm`); 5 not the staged binary as
root; 6 drift found; 130 cancelled.

Schema 3 parity: every rule that `fleetctl validate` and
`validate-fleet.py` apply today, proven by running the Python and Go
validators over `testdata/profiles/` with identical results.

Resource fields are shares of the machine, never absolute amounts.

### Tests this spec requires

- Per-OS dependency graphs: no cycles, no dangling edges.
- Every purpose, tier, OS, form factor and topology combination resolves;
  `full` equals the feasible units; skipped units carry reasons; additions
  and removals survive a preset change; a default `developer` run on a
  portable Mac reaches S6, plans no incoming remote access and requires
  disk encryption.
- Form factor changes only the five defaults (a plan comparison).
- `apply --platform` is refused.
- Interview and flags give the same config and plan digest.
- Concurrency and crash tests for the locks and every dead-man transition.
- An interrupted revert resumes toward its target and never reapplies.
- Event ordering, coalescing and spill.
- A refused root approval starts no mutation.
- Foreign content around the kit's marked blocks stays byte-identical
  across apply, revert, adopt and unmanage; a revert to baseline passes
  after adopt and unmanage.
- Removing `wskit` and its state from a fixture machine leaves every unit's
  manual checks passing.

## Edge cases

- A crash between writing the containment name and the launch
  acknowledgement: the next start empties the containment by name and
  restores.
- A reboot with an armed timer: boot recovery restores at once on both
  OSes.
- An agent-host on a portable machine: purpose keeps remote access; `plan`
  warns, and disk encryption is required.
- A unit asked for by a preset and removed by the person: the removal wins
  and survives a preset change.

## Open questions

None. A change to ADR 0005 that alters a contract here is made in the same
planning change.
